# Luna Mux 设计方案

## 1. 产品定位

Luna Mux 是面向 Coding Agent 的本地与远程终端工作台，以项目级 Session 组织窗格、Agent 和浏览器资源。

桌面支持 Windows 和 macOS，终端目标包括本地 Shell、WSL 和 SSH。连接管理、文件传输、端口转发与数据库窗格服务于项目工作流；代码编辑器、语言服务和 Git 图形界面不属于产品范围。

## 2. 核心模型

```text
Application
└── Mux Session
    ├── Pane
    │   ├── Terminal Runtime
    │   │   └── Agent 进程（可选）
    │   └── Database Runtime
    └── Browser Resource
        └── Browser Runtime（按需启动）
```

| 对象 | 职责 |
| --- | --- |
| Session | 项目容器，组织窗格与浏览器资源，也是协作和授权边界 |
| Pane | 稳定的布局单元，保存窗格类型、配置与标题 |
| Runtime | 终端、数据库或浏览器的一次运行实例，拥有连接、进程及实时状态 |
| Agent | 运行在终端中的 Coding Agent，通过适配器接入 |
| Browser Resource | Session 下的浏览器配置，独立于窗格布局 |

资源配置与运行实例分离：恢复工作区保留用户安排，启动和重启则创建新的 Runtime 身份。持久化配置不隐含恢复进程或执行命令。

## 3. 架构分工

功能模块概览：

```text
Luna Mux
├── 工作区：Session / Pane / 布局
├── 终端：本地 Shell / WSL / SSH
├── Agent 集成：启动 / Hook / MCP / 状态与协作
├── 远程工作：连接管理 / SFTP / 传输与部署 / 隧道
├── 浏览器：资源管理 / 页面自动化
├── 数据库：连接 / 查询 / 数据操作
├── AI 命令助手
└── 公共服务：授权审批 / 审计 / 凭据 / 设置 / 诊断
```

| 层次 | 职责 |
| --- | --- |
| 交互层 | React / xterm.js 展示工作区，接收用户操作 |
| 服务层 | 编排资源、Agent 集成、授权与协作 |
| 后端层 | 处理本地 PTY、SSH、数据库、文件传输、隧道和浏览器的 I/O 与生命周期 |

Tauri 连接界面与原生服务。数据库保存资源定义和配置，Runtime 后端拥有实时状态；界面通过接口和事件读取状态。UI 与 MCP 共用业务规则，避免维护两套行为。

### 3.1 终端后端

本地 PTY 与 SSH 使用统一契约，平台差异封装在后端。界面和 Agent 共享后端输出与屏幕观察能力，避免各自维护终端状态。输入由交互服务协调，防止自动操作交错，并允许用户接管。

### 3.2 Agent 与控制

适配器封装不同 Agent 的启动、Hook/MCP 和状态转换，通用服务负责协作、授权与审计。Agent 在普通终端中运行，运行期凭据绑定 Runtime，随实例结束失效。

Session 提供项目级协作范围；控制请求统一校验调用方和资源权限，涉及副作用的操作按策略确认。终端输出属于观察结果，不能直接视为命令成功。

### 3.3 浏览器与数据库

浏览器资源由 Session 共享，应用管理进程，自动化工具操作页面；浏览器窗口独立于终端布局。浏览器数据按资源隔离，可选择临时使用或保留，远程访问通过经认证的通信桥。

数据库以 Pane 接入，每个运行实例独立管理连接和查询状态，写入经过授权。

## 4. 关键约束与取舍

- 同一 Session 共享协作能力，不提供成员间的细粒度隔离；跨 Session 访问须单独授权。
- 配置持久化，运行状态随实例管理；关闭一个 Runtime 不应影响其他实例。
- 凭据存入系统凭据库，不进入工具返回或日志；资源清理限于应用拥有的数据。
- 输出、交互与后台任务有资源上限，以可控的资源消耗换取长期运行的稳定性。
