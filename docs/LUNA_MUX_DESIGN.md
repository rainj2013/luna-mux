# Luna Mux 设计方案

最后更新：2026-09-11

## 1. 产品定位

Luna Mux 是面向 Coding Agent 的本地与远程终端工作台，以项目级 Session 组织终端窗格、Agent 和浏览器资源，提供统一的终端操作与受控协作能力。

桌面支持 Windows 和 macOS，终端目标包括本地 Shell、WSL 和 SSH。连接管理、文件传输与端口转发作为终端的配套能力；代码编辑、语言服务和 Git 图形界面不属于产品范围。

## 2. 领域模型

```text
Application
└── Mux Session
    ├── Pane
    │   ├── Terminal Runtime
    │   │   └── Agent 进程（可选）
    │   └── Database Runtime（可选）
    └── Browser Resource
        └── Browser Runtime（按需启动）
```

| 对象 | 职责与归属 |
| --- | --- |
| Mux Session | 项目级容器，拥有项目根目录、终端布局和浏览器资源，也是协作与授权边界 |
| Pane | 布局树中的稳定叶节点，保存终端目标、工作目录和标题 |
| Terminal Runtime | Pane 的一次运行实例，拥有终端连接、输入输出和进程生命周期 |
| Database Runtime | 数据库 Pane 的一次运行实例，拥有数据库连接和查询状态 |
| Agent | Runtime 中被识别的 Coding Agent 进程，通过适配器接入 |
| Browser Resource | Session 下的持久化浏览器定义，独立于终端布局 |
| Browser Runtime | 浏览器资源的一次运行实例，拥有浏览器进程和自动化连接 |
| Terminal Target | 本地、WSL 或保存的 SSH 启动目标 |

资源定义与运行实例分离：Pane 保存用户的工作安排，Runtime 承载一次执行。这样重启终端无需重建布局，恢复布局也不会隐式执行命令。Browser Resource 与 Browser Runtime 采用同样的分离方式。

对象以稳定资源 ID 关联。一个 Pane 最多拥有一个实时 Runtime；重启产生新的 Runtime 身份，使旧执行记录和凭据不能指向新进程。进程 ID 与显示名称不用于资源授权。

## 3. 架构与状态归属

桌面采用 React / xterm.js 展示终端，Tauri 连接界面与 Rust 原生服务。职责分为三层：

- **交互层**：展示 Session、终端、Agent 状态和资源管理界面。
- **服务层**：管理布局、控制授权、终端交互、Agent 适配与浏览器资源。
- **后端层**：负责本地 PTY、SSH、文件传输、隧道和浏览器进程的 I/O 与生命周期。

数据库保存资源定义与配置；Runtime 后端拥有实时状态和输出。界面订阅状态变化，控制适配器把请求交给服务，服务再调用后端；UI 与 MCP 共用业务规则，避免两套入口出现不同的权限和行为。通用核心模块不反向依赖产品界面或品牌代码。

| 状态 | 唯一归属 | 生命周期 |
| --- | --- | --- |
| Session、布局与资源配置 | 数据库及对应管理服务 | 跨应用重启保存 |
| 连接、进程与输出 | Runtime 后端 | 随运行实例结束 |
| 交互记录与输入协调 | 交互管理器 | 应用运行期内保留，绑定 Runtime |
| 终端显示与滚动位置 | 界面终端实例 | 随视图维护，不作为后端状态来源 |

### 3.1 Session 与布局

主导航以 Session 和 Pane 树组织工作，连接库作为可复用的启动资源。Session 项目根目录提供默认工作目录，Pane 可单独覆盖目标与目录。Agent 在普通终端中运行，不设专用 Pane 类型。

布局采用递归分割树：叶节点引用 Pane，分支保存方向和比例，以同一结构表达任意嵌套分屏。最小化、最大化属于显示状态，不改变 Runtime 归属。完整布局更新必须恰好包含 Session 的全部 Pane，校验后串行保存，防止丢失窗格或并发覆盖。

应用重启恢复 Session、布局、Pane 配置与浏览器定义，运行实例按需启动。Runtime、进程身份和终端滚动历史不跨应用重启恢复。关闭活动终端保留用户确认，退出应用统一清理受管运行实例。

### 3.2 终端后端与数据流

本地 PTY 与 SSH 实现统一的 `TerminalBackend` 契约，提供输入、输出、屏幕观察、尺寸调整、流控、中断和关闭。界面根据后端能力启用文件传输与转发功能，平台差异封装在后端。

```text
本地 PTY / SSH
  → 增量 UTF-8 解码
  → Runtime 输出缓冲与文本屏幕模型
  → 带游标事件
  → TerminalPane / xterm.js
```

输出采用有界内存缓冲和单调字节游标，使界面与 Agent 可独立续读，无需各存一份历史。容量上限控制内存成本，代价是旧输出可能丢失，因此覆盖必须显式报告缺口。界面通过背压暂停和恢复后端读取；阻塞 PTY 写入与异步任务隔离，避免输入阻塞拖住其他 Runtime。

切换工作区保留终端实例；组件重建时用显示快照和输出游标恢复连续性。xterm.js 负责显示和终端查询应答，后端文本屏幕模型负责观察，不重复应答。渲染加速失败时回退到默认渲染器。

各后端独立管理连接与进程树，关闭一个 Runtime 不影响其他窗格。终端协议、信号和进程清理适配目标环境，不假定不同平台具有相同的 Shell 行为。

### 3.3 Agent 集成

`AgentAdapter` 封装提供方的启动适配、Hook/MCP 配置和状态转换，将提供方协议限制在适配器内，终端、授权和通知保持通用。Runtime 注入 Session、Pane、Runtime 上下文及受限凭据；Agent 身份随进程建立，随进程或 Runtime 退出清理。

提供方事件统一为工作中、等待、完成和错误状态。Luna Mux 负责状态展示、通知与终端聚焦，Agent 自身的权限请求仍由其交互界面处理。

配置限定在运行实例内，不改写用户全局配置。远程集成由用户显式启用，支持文件与通信桥按 Runtime 隔离并随生命周期清理；普通 SSH 连接不隐式安装 Agent 集成。

### 3.4 控制与终端协作

`LunaControlService` 统一应用控制操作、授权、幂等和审计。桌面与 Luna MCP 通过认证适配器调用服务；调用方身份由适配器注入，操作使用版本化契约和结构化错误。

Session 同时承载项目上下文与协作授权，避免为每对窗格另建授权关系。加入同一 Session 意味着允许终端观察、输入及 Agent 协作，不提供同 Session 内的细粒度隔离；跨 Session 访问不能由相同目标或进程关系推断。关闭 Runtime、启动传输和隧道等操作遵循独立审批策略；资源发现不返回凭据。

终端交互遵循“观察 → 输入 → 等待新状态 → 再决策”：

- 输入统一表达为文字、按键或粘贴，依据终端模式编码。
- 原始输出用于增量读取，屏幕快照提供当前文字、光标和终端模式。
- 可配置提示规则描述终端程序的交互状态，等待只接受新产生的相关状态。
- 交互记录支持去重、结果续读和取消等待；输入协调防止交错写入，并允许用户接管。

交互先登记执行并捕获输出游标，再发送输入；重试复用同一记录，超时后继续观察而不重发。写入可能部分完成，失败不能自动当作“未执行”。同 Runtime 的自动输入发生冲突时立即返回，避免排队后执行已过时的命令；用户接管结束旧观察。

原始输出保留时间顺序，屏幕模型表达覆盖写、清屏后的当前状态，两者分别服务增量读取和状态判断。模型由后端输出派生，隐藏窗格仍可观察；它与显示渲染分工，不是第二份输出历史。提示规则保持程序无关，且必须排除交互开始前的旧提示。

输出、解析与等待都有资源上限。交互记录不复制输出历史，去重限于当前应用运行期。PTY 将输入回显、程序输出和后台输出混在同一流中，因此提示匹配和静默只表示观察条件满足，不能推导命令成功；取消等待也不等同于中断进程。

### 3.5 浏览器资源

浏览器以 Session 为共享单位，让同一项目中的用户与 Agent 使用一致的页面上下文；代价是它们共享浏览器状态，不具备彼此隔离的页面权限。配置目录按资源隔离，跨 Session 不复用配置。每个 Session 共享一个活动浏览器 Runtime，首次自动化调用可按需启动。

浏览器在桌面独立 Chrome 窗口中运行，不参与终端布局，避免把网页标签与终端 Pane 的布局、尺寸和生命周期混为一体。

应用负责浏览器生命周期，`agent_browser` 负责页面自动化。自动化绑定 Session 的现有页面，普通导航复用该页面；网页操作不能自行启动或替换浏览器进程。

CDP 仅绑定本地回环地址，端口和连接信息属于临时运行状态。远程 Agent 通过经认证的 Runtime 通信桥访问 Session 浏览器，原始 CDP 不转发到远端。远程开发服务使用独立 SSH 隧道，浏览器资源不拥有隧道。

工具按资源归属路由：应用资源由 Luna MCP 控制，网页内容由 `agent_browser` 操作，开发与主机工作使用对应原生工具。终端 Pane 与浏览器标签页是不同资源。

### 3.6 数据库窗格

数据库窗格是 Session 中的一种 Pane 类型，每个窗格拥有独立的 Database Runtime 和连接 Profile。支持 SQLite、MySQL/MariaDB 与 PostgreSQL，可浏览表和视图、查看字段/索引/外键、执行带分页的 SQL 查询，以及导入导出 CSV、JSON 和 SQL；SQLite 还支持部分结构编辑。

Profile 保存连接配置和系统凭据引用，密码始终由系统凭据库管理。Pane 默认以只读模式连接，DML 与 DDL 写入分别经过会话授权；Runtime 仅保存活动连接和查询状态，随窗格关闭或应用退出清理。

## 4. 数据与安全边界

`product/product.json` 统一定义产品身份，运行时读取生成的元数据。数据库、系统凭据服务、应用设置和浏览器目录与其他产品隔离。

持久化资源定义与临时运行状态分离。配置迁移采用显式、幂等的事务流程；外部数据导入由用户选择，凭据导入单独授权并通过系统凭据库处理。

WebView 仅访问显式注册的原生能力。凭据保存在系统凭据库，不进入工具返回或日志。控制审计记录调用方、目标、操作与结果摘要，不保存敏感输入正文。
