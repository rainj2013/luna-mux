# Luna Mux 设计方案

## 1. 产品定位

Luna Mux 是面向 Coding Agent 的本地与远程终端工作台，以项目级 Session 组织窗格、Agent 和浏览器资源。

桌面支持 Windows 和 macOS，终端目标包括本地 Shell、WSL 和 SSH。连接管理、文件传输、端口转发与数据库窗格服务于项目工作流；代码编辑器、语言服务和 Git 图形界面不属于产品范围。

## 2. 核心模型

```text
Application
└── Mux Session
    ├── Pane
    │   ├── Terminal Runtime
    │   │   └── Agent 进程（可选）
    │   └── Database Runtime
    └── Browser Resource
        └── Browser Runtime（按需启动）
```

| 对象 | 职责 |
| --- | --- |
| Session | 项目容器，组织窗格与浏览器资源，也是协作和授权边界 |
| Pane | 稳定的布局单元，保存窗格类型、配置与标题 |
| Runtime | 终端、数据库或浏览器的一次运行实例，拥有连接、进程及实时状态 |
| Agent | 运行在终端中的 Coding Agent，通过适配器接入 |
| Browser Resource | Session 下的浏览器配置，独立于窗格布局 |

资源配置与运行实例分离：恢复工作区保留用户安排，启动和重启则创建新的 Runtime 身份。持久化配置不隐含恢复进程或执行命令。

## 3. 架构分工

功能模块概览：

```text
Luna Mux
├── 工作区：Session / Pane / 布局
├── 终端：本地 Shell / WSL / SSH
├── Agent 集成：启动 / Hook / MCP / 状态与协作
├── 远程工作：连接管理 / SFTP / 传输与部署 / 隧道
├── 浏览器：资源管理 / 页面自动化
├── 数据库：连接 / 查询 / 数据操作
├── AI 命令助手
└── 公共服务：授权审批 / 审计 / 凭据 / 设置 / 诊断
```

| 层次 | 职责 |
| --- | --- |
| 交互层 | React / xterm.js 展示工作区，接收用户操作 |
| 服务层 | 编排资源、Agent 集成、授权与协作 |
| 后端层 | 处理本地 PTY、SSH、数据库、文件传输、隧道和浏览器的 I/O 与生命周期 |

Tauri 连接界面与原生服务。数据库保存资源定义和配置，Runtime 后端拥有实时状态；界面通过接口和事件读取状态。UI 与 MCP 共用业务规则，避免维护两套行为。

### 3.1 终端后端

本地 PTY 与 SSH 使用统一契约，平台差异封装在后端。界面和 Agent 共享后端输出与屏幕观察能力，避免各自维护终端状态。输入由交互服务协调，防止自动操作交错，并允许用户接管。

### 3.2 Agent 与控制

适配器封装不同 Agent 的启动、Hook/MCP 和状态转换，通用服务负责协作、授权与审计。Agent 在普通终端中运行，运行期凭据绑定 Runtime，随实例结束失效。

Session 提供项目级协作范围；控制请求统一校验调用方和资源权限，涉及副作用的操作按策略确认。终端输出属于观察结果，不能直接视为命令成功。

### 3.3 浏览器与数据库

浏览器资源由 Session 共享，应用管理进程，自动化工具操作页面；浏览器窗口独立于终端布局。浏览器数据按资源隔离，可选择临时使用或保留，远程访问通过经认证的通信桥。

数据库以 Pane 接入，每个运行实例独立管理连接和查询状态，写入经过授权。

## 4. 关键约束与取舍

- 输入统一表达为文字、按键或粘贴，依据终端模式编码。
- 原始输出用于增量读取，屏幕快照提供当前文字、光标和终端模式。
- 可配置提示规则描述终端程序的交互状态，等待只接受新产生的相关状态。
- 交互记录支持去重、结果续读和取消等待；输入协调防止交错写入，并允许用户接管。

交互先登记执行并捕获输出游标，再发送输入；重试复用同一记录，超时后继续观察而不重发。写入可能部分完成，失败不能自动当作“未执行”。同 Runtime 的自动输入发生冲突时立即返回，避免排队后执行已过时的命令；用户接管结束旧观察。

原始输出保留时间顺序，屏幕模型表达覆盖写、清屏后的当前状态，两者分别服务增量读取和状态判断。模型由后端输出派生，隐藏窗格仍可观察；它与显示渲染分工，不是第二份输出历史。提示规则保持程序无关，且必须排除交互开始前的旧提示。

输出、解析与等待都有资源上限。交互记录不复制输出历史，去重限于当前应用运行期。PTY 将输入回显、程序输出和后台输出混在同一流中，因此提示匹配和静默只表示观察条件满足，不能推导命令成功；取消等待也不等同于中断进程。

### 3.5 浏览器资源

浏览器以 Session 为共享单位，让同一项目中的用户与 Agent 使用一致的页面上下文；代价是它们共享浏览器状态，不具备彼此隔离的页面权限。每个 Session 共享一个活动浏览器 Runtime，首次自动化调用可按需启动。

浏览器在桌面独立 Chrome 窗口中运行，不参与终端布局，避免把网页标签与终端 Pane 的布局、尺寸和生命周期混为一体。

Browser Resource 持有“保留浏览器数据”设置，默认关闭。关闭时，每个 Runtime 使用独立临时配置目录并在浏览器关闭后删除；开启时，同一 Session 的该 Browser Resource 跨多次 Runtime 启动复用固定配置目录，保留 Cookie、登录状态和站点存储。设置只能在浏览器停止时修改；从开启改为关闭时立即删除固定配置目录。两种模式都不复制本机 Chrome 的 Cookie。启动时只清理崩溃残留的临时配置；删除 Browser Resource 或 Session 时清理对应持久配置和下载。删除操作须限制在产品数据目录内。

BrowserRuntimeManager 通过 CDP 让绑定页面的配色跟随应用主题，选择“跟随系统”时由 Chrome 跟随操作系统。截图默认开启元素标注。

复用固定配置目录前，BrowserRuntimeManager 通过原生进程元数据检查是否仍有未关联的 Chrome 主进程使用该目录。匹配限定为完整目录路径，排除其他资源和 Chrome 子进程；发现占用时，在修改配置和启动进程前提示用户关闭旧窗口，保留浏览器数据。清理已退出的旧 Runtime 记录只删除临时目录，不提前写入保留目录的 Preferences。检测只读取进程信息，不接管或关闭未关联窗口。Chrome 在 CDP 就绪前退出时立即返回退出原因；就绪、目标查询和启动标签页清理统一使用禁用代理、有请求时限、不跟随重定向的回环客户端。HTTP 和 WebSocket 初始化错误不返回原始端点或响应内容，WebSocket 连接也设有时限。

Browser TAB 使用概览、浏览器设置和 Agent 工具的分栏导航。概览显示运行状态、地址和配置摘要，摘要行可跳转对应设置；设置使用统一开关和紧凑行，工具说明保持简短。页面切换保留代理编辑组件，离开输入时自动保存。导航支持方向键、Home/End 和清晰的焦点。代理和浏览器数据卡片保持等宽，较窄区域改为单列。

浏览器代理卡片与浏览器配置卡片使用等宽网格，同一行高度一致。Browser Resource 保存代理地址和独立启用开关；关闭开关保留地址，启动时使用系统默认代理设置。开关切换立即保存，地址在失焦或按 Enter 时保存，无需保存按钮；保存失败时保留错误提示并恢复实际开关状态。设置在下次启动浏览器时生效。旧数据库和缺少启用字段的资源 JSON 保持原有已配置代理的行为。

应用负责浏览器生命周期，`agent_browser` 负责页面自动化。自动化绑定 Session 的现有页面，普通导航复用该页面；网页操作不能自行启动或替换浏览器进程。

Browser Resource 按上游 profile 持久化 Agent 工具组选择：Core 始终启用；Network、Debug、Tabs、State/Auth Vault、React、Mobile 与 WebMCP 默认关闭，可在 Browser 页分类勾选。本地和远程 Agent 使用同一选择。保存会更新当前 Runtime 的注册信息，新 MCP 连接立即采用；已运行的 Agent 需重启后重新发现工具，因为当前客户端不会响应工具列表热变更。Browser Runtime 始终启用 Chrome WebMCP 接口，但只有启用 WebMCP 工具组后 Agent 才能发现页面注册的工具。React 检查须在打开页面时启用 `react-devtools`。Luna Mux 不附带上游 skills，以免其 CLI 和具名会话指引与受管浏览器契约冲突。

Agent 注入指引说明可选工具组，以及启用 Debug 后的批量调用、无障碍审计、截图与快照差异比较；Core 的增量观察和输出收窄始终可用。

内置 agent-browser 固定为 0.39.1，下载脚本分别校验 Windows x64、macOS x64/ARM64 的发布 SHA-256。Browser MCP 配置默认启用 `useSystemCa`，让 CLI 自身的 HTTPS 请求信任操作系统证书库，同时保留证书验证；不会改变受管 Chrome 的证书设置。工具的 `caCert` 指向 Luna Mux 主机上的 PEM 文件，WSL/SSH Agent 也使用该主机路径。MCP 桥直接保留上游 `structuredContent.response.code`；返回 `outcome_unknown` 表示操作可能已经执行，Agent 必须先用只读状态检查结果再决定是否重试。作用域快照可以读取所选自定义元素的 Shadow DOM。实验性 Obscura 不接入现有 Chrome/CDP Runtime。

CDP 仅绑定本地回环地址，端口和连接信息属于临时运行状态。远程 Agent 通过经认证的 Runtime 通信桥访问 Session 浏览器，原始 CDP 不转发到远端。远程开发服务使用独立 SSH 隧道，浏览器资源不拥有隧道。

工具按资源归属路由：应用资源由 Luna MCP 控制，网页内容由 `agent_browser` 操作，开发与主机工作使用对应原生工具。终端 Pane 与浏览器标签页是不同资源。

### 3.6 数据库窗格

数据库窗格是 Session 中的一种 Pane 类型，每个窗格拥有独立的 Database Runtime 和连接 Profile。支持 SQLite、MySQL/MariaDB 与 PostgreSQL，可浏览表和视图、查看字段/索引/外键、执行带分页的 SQL 查询，以及导入导出 CSV、JSON 和 SQL；SQLite 还支持部分结构编辑。

Profile 保存连接配置和系统凭据引用，密码始终由系统凭据库管理。Pane 默认以只读模式连接，DML 与 DDL 写入分别经过会话授权；Runtime 仅保存活动连接和查询状态，随窗格关闭或应用退出清理。

## 4. 数据与安全边界

`product/product.json` 统一定义产品身份，运行时读取生成的元数据。数据库、系统凭据服务、应用设置和浏览器目录与其他产品隔离。

持久化资源定义与临时运行状态分离。配置迁移采用显式、幂等的事务流程；外部数据导入由用户选择，凭据导入单独授权并通过系统凭据库处理。

WebView 仅访问显式注册的原生能力。凭据保存在系统凭据库，不进入工具返回或日志。控制审计记录调用方、目标、操作与结果摘要，不保存敏感输入正文。
- 同一 Session 共享协作能力，不提供成员间的细粒度隔离；跨 Session 访问须单独授权。
- 配置持久化，运行状态随实例管理；关闭一个 Runtime 不应影响其他实例。
- 凭据存入系统凭据库，不进入工具返回或日志；资源清理限于应用拥有的数据。
- 输出、交互与后台任务有资源上限，以可控的资源消耗换取长期运行的稳定性。
