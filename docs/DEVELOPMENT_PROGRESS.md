## Decision log

| Date | Decision |
| --- | --- |
| 2026-08-12 | Luna Mux is an independent product and repository, not a Luna Remote feature branch. |
| 2026-08-12 | Luna Remote is only an implementation and proven-capability donor. Luna Mux does not preserve its architecture, navigation, terminology, data model, or UX unless each part independently fits the Luna Mux design. |
| 2026-08-12 | Windows and macOS are both first-release platforms. Distribution signing is out of scope. |
| 2026-08-12 | Local and SSH terminals share one TerminalPane and differ only through capabilities. |
| 2026-08-12 | Agents stop when Luna Mux exits; a thin `TerminalBackend` preserves a future daemon extension point for live runtimes. |
| 2026-08-12 | Browser runs locally; remote development services use SSH local forwarding. |
| 2026-08-14 | Browser Resources are local Chrome lifecycle objects only. Remote services use the independent SSH tunnel workflow and a loopback URL; Browser creation does not select or own an SSH Pane. |
| 2026-08-14 | The Agent view is an observation and response center ordered by attention needs. `Start Agent` is retained only as a convenience that creates a normal terminal Pane and automatically executes a selected registered launch profile; `Add Pane` remains terminal-only. |
| 2026-08-12 | Luna Remote updates are selectively ported by commit into in-repository core boundaries. |
| 2026-08-12 | Unreferenced Luna Remote screenshots and design images are removed; build-required icons remain temporarily until Luna Mux visual identity is designed. |
| 2026-08-12 | Terminal Runtime output cursors count UTF-8 bytes and are capped at JavaScript's maximum safe integer so Rust and TypeScript retain exact cursor values. |
| 2026-08-12 | Connection backups use an in-memory preview snapshot and a single SQLite transaction; source files are never mutated and credentials are excluded. |
| 2026-08-12 | Direct Luna Remote import opens SQLite with read-only/query-only flags, allowlists portable settings, clears source-private background paths, and requires a second confirmation before reading system credentials. |
| 2026-08-12 | `MuxSession` is the project-level persistent container; it owns multiple panes. A Terminal pane owns one replaceable `TerminalRuntime`, and an optional Coding Agent runs inside that runtime. `runtimeId` is used for transport events; `sessionId` is not the new domain term. |
| 2026-08-12 | Luna Mux application icons use editable SVG masters and one Tauri generation command; PNG/ICO are byte-checked, ICNS structure is validated, and old SSH-centric files are removed from the independent repository. |
| 2026-08-12 | Agent operation of Luna Mux is a separate control-plane concern from agent-to-agent MCP. `LunaControlService` is the sole core entry point; future transports authenticate callers and inject scoped grants. |
| 2026-08-12 | A mock terminal backend is the conformance fixture for local PTY and future daemon implementations; TerminalPane and Mux Session code must depend only on `TerminalBackend`, not on SSH internals. |
| 2026-08-12 | `portable-pty` 0.9 is the local PTY candidate. The probe responds to ConPTY's initial `ESC[6n` cursor query; production xterm.js remains responsible for terminal protocol responses. |
| 2026-08-12 | Local and SSH runtimes are routed through one composite backend; local PTY records own writer, master, child killer, output cursor, and event lifecycle. |
| 2026-08-12 | The Luna Mux primary UI hierarchy is Mux Session -> Pane -> Terminal Runtime. Connections are reusable SSH target definitions and remain a secondary pane source, never a top-level workspace. |
| 2026-08-12 | Session and pane definitions persist, but live processes do not. Startup restores the recursive layout with stopped panes, preserving the future daemon extension point without requiring a daemon in v1. |
| 2026-08-12 | Windows exposes PowerShell plus discovered WSL distributions through the same local PTY backend. macOS resolves the user's login shell dynamically and uses the PTY's process group for cleanup. |
| 2026-08-12 | Control transports never deserialize caller identity from request JSON. An authenticated adapter resolves opaque tokens to in-memory `ControlCaller` grants before calling `LunaControlService`; no raw database access is available to adapters. |
| 2026-08-12 | Session is the only top-level workspace identity. Pane tabs are not a second top-level navigation system; Connections default to a collapsed secondary library used to create SSH panes. |
| 2026-08-12 | Agent launch commands and adapter selection belong to the native launch-profile registry. The UI persists only `launchProfileId`, target, cwd, and presentation fields. |
| 2026-08-12 | Codex hooks are injected per Luna-managed launch, so M4.1/M4.2 do not mutate global user configuration. Optional persistent adapter installation remains a separate preview/back-up/uninstall task. |
| 2026-08-12 | Managed Agent hook events retain only lifecycle metadata. Prompt contents, tool inputs, and tool outputs are not stored in the dashboard event buffer. |
| 2026-08-12 | Hook bearer tokens are passed only through process environment, scoped to one runtime identity, and revoked when that runtime exits. |
| 2026-08-12 | Agent history and unread state are bounded in-memory state for v1; Pane launch definitions persist but no runtime or Agent process/history survives application exit. |
| 2026-08-12 | System notifications are emitted only for waiting, completed, and error states and are suppressed for the matching focused terminal Pane. |
| 2026-08-12 | Luna-managed Codex launches add only an exact `127.0.0.1` network allow rule for the authenticated Hook receiver and do not mutate global Codex network settings. Windows Hook definitions use `commandWindows` with PowerShell's call operator; macOS and WSL use their native command form. |
| 2026-08-12 | Persistent Codex adapter installation is optional and ownership-scoped. Luna Mux previews and backs up `hooks.json`, preserves unrelated handlers and metadata, detects stale Windows command definitions, and uninstalls only its own marked handlers. |
| 2026-08-13 | Agent-callable transfer and tunnel actions use the same `LunaControlService` grant, approval, idempotency, and audit boundary as terminal control; side-effect managers remain behind a narrow mockable interface. |
